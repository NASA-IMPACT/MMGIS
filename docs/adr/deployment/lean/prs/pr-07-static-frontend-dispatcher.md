# PR 7 — Static frontend: SERVER flag + dispatcher + ServiceUrls static mode

**Depends on:** PR 1. **Blocks:** PR 8, PR 9.

**Goal:** Teach the Essence bundle a second "static" personality — flip `mmgisglobal.SERVER` to a build-substituted value, activate the dormant dispatcher branch with a per-call handler table, make `ServiceUrls` resolve external sidecar URLs with no same-origin fallback, and short-circuit the backend-dependent surfaces (login, WebSocket, credentialed image fetches, mission deeplinks).

## In plain English

A published dashboard is the same web app as the admin Configure tool, just frozen and backend-less. Today that web app always assumes a live server is sitting behind it, answering its data requests. This PR teaches the app a second way to behave: when it is built in "static" mode it stops calling a server and instead answers each request from data baked into the page, points at external services, computes the answer in the browser, or quietly disables the feature.

The capability to detect this mode already half-exists in the code — there is a branch that checks "am I talking to a real server?" — but it currently just prints a warning and gives up. This PR turns that branch into a real switchboard. Each of the app's roughly forty named requests gets routed to one of four outcomes: serve a frozen answer, redirect to an outside service, calculate it locally, or politely do nothing.

It also turns off the things that make no sense without a backend. There is no login box (nobody to log in to), no live-collaboration socket (no server to broadcast through), no credentialed image loading (the dashboard reads public files anonymously), and no "go fetch a different mission" behavior (a dashboard only ever shows its one baked mission).

None of this affects the existing full app. The switch is decided when the app is built, not when it runs, and the normal build still produces the normal server-talking app. This work is separate from the server-side mode used by the rest of the lean effort; it is purely about how the browser bundle behaves.

## Implementation steps

1. **Flip the SERVER flag.** Add `SERVER` to `env.raw` in `configuration/env.js` (default `"node"`; the static build overrides to `"static"`). Change `public/index.html` line 341 from the `"node"` literal to the `%SERVER%` placeholder so `InterpolateHtmlPlugin` substitutes it the same way it does `%NODE_ENV%`. Confirm a normal build still emits `mmgisglobal.SERVER = "node"`.
2. **Build the dispatcher table.** Create `src/pre/staticHandlers.js` exporting a `STATIC_HANDLERS` map keyed by every name in `calls.js`'s `c` registry. Implement each per the [`api.md`](../api.md) disposition: Bake reads from `STATIC_MISSION_CONFIG`; Drop returns a graceful no-op/error; Compute computes client-side (`proj42wkt`/`query_tileset_times` can be no-ops until PR 9 lands); there are no Reroute entries in the dispatcher itself (`getminmax`'s reroute to TiTiler is a direct-`$.ajax` call-site, owned by PR 9).
3. **Activate the branch.** In `src/pre/calls.js`, replace the warn-and-bail block (L169–173) with: if `SERVER !== 'node'`, look up `STATIC_HANDLERS[call]`, invoke it with `(data, success, error)`, and return; otherwise fall through to the existing `$.ajax`. Re-grep and assert every `c[]` entry has a handler (count is 40).
4. **Static-mode ServiceUrls.** In `ServiceUrls.js`, gate the same-origin `getLocalBaseUrl()` fallback on `SERVER === 'node'`; in static mode require a per-layer or global configured URL and warn (don't silently 404) if absent. Add `buildTipgUrl`/`buildVeloserverUrl` companions to the getters. Add `LayerManager/lib/utils/titiler.ts` to the static path (route through the baked TiTiler URL or skip colormap fetches).
5. **Codegen the baked config.** Add `bakeStaticConfig` to `API/updateTools.js`, writing the mission config into `src/pre/staticConfig.js` using the same `fs.writeFileSync` pattern as `tools.js`/`components.js`. (Content source is PR 8's publish flow; this PR adds the codegen seam and an empty/passthrough bake.)
6. **Short-circuits.** Login: early-return at the top of `Login.init` (Login.js:66) when `SERVER !== 'node'`. WebSocket: gate the connect block (essence.js:414) on `SERVER === 'node'`. LandingPage: insert the deeplink override before the mission-resolution fallback (LandingPage.js:49–70). Viewer: set `ajaxWithCredentials` false in static mode (Viewer_.js:208). Identifier: skip the recursive `getbands` call in static mode (IdentifierTool.js:803), forcing the legend-RGB fallback. Coordinates: hide the elevation column (`#mouseElev`) in static mode (Coordinates.js:623–624) so the Dropped `getbands` readout isn't left blank.

## Verification

- **Server build unchanged.** Today's `npm run build` produces `mmgisglobal.SERVER = "node"`; the admin still hits same-origin `/titiler`, the login modal appears, the WebSocket connects, and every `calls.api` call goes through `$.ajax`.
- **Static build routes `calls.api()` traffic through the table.** A build with `SERVER=static` resolves **every `calls.api(name, …)`-routed request** through a `STATIC_HANDLERS` handler (no "Unknown api call" or "only for node servers" warnings) — confirm in the browser network tab. This does *not* mean *zero* `/api/*` calls: a handful of dispatcher-named endpoints are issued via raw `$.ajax` using `calls.<name>.url` and **bypass the dispatcher entirely**. Those are short-circuited at their call sites — `getminmax` by PR 9 (reroute to TiTiler), and `getprofile` + Measure `getbands` by PR 7 itself (elevation profile disabled in static mode, see the MeasureTool scope row). The "no backend traffic" outcome is therefore a joint property of PR 7 + PR 9, not the dispatcher alone.
- **ServiceUrls.** Static mode returns configured absolute sidecar URLs and never the same-origin `/titiler` path; missing config warns rather than silently 404s. Server mode still returns same-origin paths.
- **Short-circuits.** Static build: no login modal, no WebSocket connection attempt, OSD image loads succeed anonymously, and a dashboard URL with `?mission=other` or `?forcelanding=true` ignores those params (stripped from the URL) and loads the baked mission. Identifier on a plain-`.tif` layer shows the legend-RGB readout with no `getbands` request. The coordinates-bar elevation column is hidden (no perpetually-blank readout).
- Grep confirms `STATIC_HANDLERS` covers all 40 `c[]` entries and that the only `SERVER`-literal source is `public/index.html` (now a placeholder) + `env.raw`.

## Rollback

`git revert` the PR. The change is keyed entirely on the build-time `SERVER` value, which defaults to `"node"`; server/full builds are unaffected regardless. No data migration, no server-side mount changes (those are PRs 2–6).

## Implementation notes & gotchas

- **Login skip belongs in `Login.js`, not `essence.js`.** The login modal is built and shown by `Login.init` (`src/essence/Ancillary/Login/Login.js:66`), invoked from the `UserInterface_*` files; `essence.js` only references `#loginModal` (focus handling, L122). Put the static-mode early-return in `Login.init`, beside the existing `AUTH == 'off'` guard.
- **Direct-`$.ajax` bypass (some endpoints skip the dispatcher).** Activating the dormant branch in `calls.js`'s `api()` only intercepts calls routed through `calls.api(name, …)`. Several dispatcher-named endpoints are issued via raw `$.ajax` reading `calls.<name>.url`, so they bypass `STATIC_HANDLERS` and are *not* covered by PR 7:
  - `getminmax` (single-band COG) — Map_.js:~2074–2075. **Owned by PR 9** (call-site reroute to the external TiTiler); the "no /api/*" outcome for this one depends on PR 9.
  - `getprofile` (elevation profile) — Map_.js:2022 and MeasureTool.js:1484–1493. **Owned by PR 7** (decided 2026-06-08: disable the elevation profile in static mode — see the MeasureTool scope row).
  - `getbands` (Measure band profile) — MeasureTool.js:1598–1599. **Owned by PR 7**, same Measure decision (hidden with the elevation profile). *(IdentifierTool's `getbands` at IdentifierTool.js:803 IS routed through `calls.api()`, so PR 7 handles that one too — see Scope row above.)*

  `proj42wkt` and `query_tileset_times` DO go through `calls.api()`, so the dispatcher handles them (`proj42wkt` → Compute via `proj4js`; `query_tileset_times` → Drop, since PR 9 disables the histogram — both finalized by PR 9).
- **`SERVER` interpolation requires an `env.js` edit.** `InterpolateHtmlPlugin` only substitutes keys present in `env.raw`, so `SERVER` must be added there for the `%SERVER%` placeholder in `public/index.html` to resolve. (PR 1 added the other `STATIC_*` keys to the same map, so the seam is established.)
